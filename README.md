# 楽曲アナライザ

自分の楽曲ファイル（WAV / AIFF / FLAC / MP3 / Ogg / AAC など）を読み込んで、解析と編集をするブラウザツールです。インストールは不要で、音声はすべてPC内で処理されます（外部には送信されません）。

**使う: https://airman8787.github.io/music-analyzer/**

`index.html` をダウンロードして、ローカルで開いても同じように使えます。

元: [airman8787/tab-analyzer](https://github.com/airman8787/tab-analyzer)（MIT）。タブ録音を外し、ファイル専用にして編集機能を足しました。

## いちばん簡単な使い方（かんたん表示）

1. 曲ファイルを枠にドロップします。
2. 「おまかせで仕上げる」に、専門用語を使わない診断（音量・音割れ・迫力・音色・低音の広がり・高音の欠け）が出ます。
3. ジャンルを選んで「✨ 音を良くする」を押します。
4. 「▶ 仕上げた音」「▶ 元の音」で聴き比べます（音量をそろえて再生するので、公平に比べられます）。
5. 良ければ「💾 仕上げた音を保存」（ファイル名の末尾に `_master` が付きます）。

最初は「かんたん表示」で、診断・おまかせ・公開前チェックだけを表示します。1. の「くわしい表示」に切り替えると、すべての解析と、マスタリングの細かい設定（10.）が出ます。

## はじめかた

1. 「1. 読み込み」の枠に音声ファイルをドロップするか、「ファイルを選ぶ」で選びます。**何曲でもまとめて入れられます。**
   - 1 曲目が A として 2.〜10. に表示され、残りの曲も順番に自動で解析されて「曲リスト」に並びます（ラウドネス・ピーク・PLR・PSR・LRA・BPM・キー・チェック結果）。
   - リストの「A で表示」（または曲名のクリック）で、その曲の詳しい結果に切り替わります。
   - 「解析した曲を 8. に保存（音声つき）」にチェックすると、解析した曲が 8. の保存一覧にも入ります。一覧は CSV で保存できます。
2. 「2. 概要」と「3. 公開前チェック」で、音圧・ダイナミクス・周波数バランスなどの結果と対処のしかたを見ます。
3. 「4. 波形」はクリックで再生、ドラッグで範囲を選べます（選んだ範囲は、編集や書き出しの対象にできます）。

## アルバムとしてまとめて仕上げる（1. の曲リスト）

曲リストに入れた全曲に、10. の「おまかせマスタリング」と同じ仕上げをかけて、ZIP（FLAC 24bit / WAV 24bit / WAV 16bit）で保存します。ファイル名は `01_曲名_master.wav` のように曲順の番号付きです。

- 「全曲の音量をそろえる」（おすすめ）：まず各曲をジャンルの目安で仕上げ、いちばん小さく仕上がった曲（音質優先で止まった曲を含む）の音量に、0.5 dB 以上大きい曲を合わせて仕上げ直します。後から音量を下げるより、リミッターのかかりが浅くなるためです。
- 「各曲ともジャンルの目安に合わせる」：曲ごとに目安どおり仕上げます（音質優先で止まった曲は小さめになります）。
- 確認：60 秒の 3 曲（性格の違う曲）を EDM の目安で仕上げ、保存した ZIP を展開して計測すると、音量の差は最大 0.16 dB、トゥルーピークはすべて −1 dBTP 以下でした。

## A/B 比較（2曲を聴き比べる）

1. 「1. 読み込み」の曲リストで、比べたい曲の「B で比べる」を押します。最初に 2 曲だけまとめて入れたときは、自動で A と B に入ります。
2. 上のバーの ▶ / A / B ボタン、または `X` キーで切り替えます。
3. 公平に比べるときは、試聴音量を「ラウドネス一致」にしてください（大きい音のほうが良く聞こえやすいためです）。

- 切り替えても再生位置は同じままで、前後の無音をトリムした状態で頭がそろいます。ループ再生中も切り替えられます。
- B の再生中も波形に再生位置が出て、クリックするとその位置へ移動します。
- 上のバーに「B は A より -7.5 dB」のように音量差が出ます。
- B は保存されず、ページを閉じると消えます。残したい曲は、A として読み込んで「8. 保存して比較」で保存してください。

## おまかせマスタリング（かんたん表示の「音を良くする」／くわしい表示の 10. の最初のタブ）

ジャンルを選んで実行すると、曲全体に次の順で処理をかけます（くわしい表示では、各段のオン・オフと強さを変えられます）。

1. **オート EQ**：「ジャンルの目安」か「5. で選んだターゲット（好きな曲から作ったもの）」との音色の差を、約 1 オクターブで平滑化し、帯域を固定した幅の広い 5 バンド（90 Hz シェルフ・250 Hz・800 Hz・2.5 kHz・8 kHz シェルフ）の最小二乗で補正します（最大 ±3 dB × かかり具合）。曲のキーや楽器の音程による細かい山谷は追いません。20 Hz 以下の超低域カットもかけられます。
2. **低域のモノラル化**（自動：低音が左右に広がりすぎのときだけ）：サイドからゼロ位相の 4 次ローパス成分を引き、120 Hz 以下の左右差だけをなくします。上の帯域の位相とステレオ感は変わりません。
3. **耳に痛い瞬間を抑える**（試験的・既定はオフ）：4.2 kHz 付近が中域と比べて突出した瞬間だけ下げるダイナミック EQ。
4. **オートコンプ**：左右連動の RMS 型。しきい値は曲の大きい部分から自動で決め、そこで約 1.5 / 2.5 / 4 dB 圧縮します（弱め / ふつう / 強め）。
5. **リミッター**：4 倍オーバーサンプリングでピークを検出する先読みリミッターで、目標の統合ラウドネスに合わせます。最後に解析と同じ精密なトゥルーピークで確かめ、上限を超えていたら補正します。上限の既定は、Spotify の推奨に合わせて、目安が −14 LUFS より大きいジャンルでは −2 dBTP、それ以外は −1 dBTP です。
6. **音質優先**（既定オン）：PSR（曲の大きい部分のピークと短時間ラウドネスの差）が 8 dB 以上、最大ショートタームラウドネスが −10 LUFS 以下（3. の公開前チェックと同じ目安）に収まるところで、音量を上げるのを止めます（仕上げ後の解析で目安を割らないよう、0.2〜0.3 dB の余裕を持たせます）。止めたときは、その理由と止めた値を表示します。配信サービスは −14 LUFS 前後にそろえて再生するので、それ以上大きくしても大きくは聞こえません。

   実際の曲（Suno で作った 2 曲・MP3）で、J-POP の目安で仕上げたときの結果：

   | | 音量 | PSR | 最大ショートターム | Opus 96 kbps に変換後のピーク |
   |---|---|---|---|---|
   | 曲 1（処理前） | −14.8 LUFS | 10.1 dB | −12.7 LUFS | −2.6 dBTP |
   | 曲 1（以前の版：PSR だけを見ていた） | −10.6 LUFS | 7.9 dB（潰れ気味の警告） | −8.7 LUFS（警告） | −0.4 dBTP（−1 超え 3 か所） |
   | 曲 1（今の版） | −12.0 LUFS | 9.2 dB | −10.3 LUFS | −1.1 dBTP |
   | 曲 2（処理前） | −15.3 LUFS | 10.0 dB | −12.5 LUFS | −2.1 dBTP |
   | 曲 2（今の版） | −11.9 LUFS | 9.3 dB | −10.3 LUFS | −0.4 dBTP（−1 超え 1 か所） |

   ツールの統合ラウドネス・LRA・トゥルーピークは、ffmpeg の EBU R128 測定と一致しました（曲 1：−14.81 / −14.8 LUFS、5.49 / 5.5 LU、−2.80 / −2.8 dBTP）。

| ジャンル | 目標 | 上限 | コンプ | 音色の傾向（汎用の目安との差） |
|---|---|---|---|---|
| 配信向け | −14 LUFS | −1 dBTP | ふつう | なし |
| J-POP・ポップス | −9 LUFS | −2 dBTP | ふつう | 低域 +1・張り +0.5・高域 +1 dB |
| ロック・バンド | −9 LUFS | −2 dBTP | ふつう | 張り +1・高域 +0.5 dB |
| EDM・ダンス | −7.5 LUFS | −2 dBTP | 強め | 低域 +3・張り −0.5・高域 +1.5 dB |
| ヒップホップ・トラップ | −8 LUFS | −2 dBTP | ふつう | 低域 +3.5・高域 +0.5 dB |
| R&B・バラード | −11 LUFS | −2 dBTP | ふつう | 低域 +1.5・高域 +0.5 dB |
| アコースティック・弾き語り | −13 LUFS | −2 dBTP | 弱め | 低域 −1・高域 +0.5 dB |
| ジャズ | −14 LUFS | −1 dBTP | 弱め | 高域 −0.5 dB |
| クラシック・映画音楽 | −18 LUFS | −1 dBTP | なし | 高域 −1 dB |

- ジャンルの値は、市販曲でよく見られる傾向をもとにした**大まかな目安**です（特定の調査の実測値ではありません）。「汎用の目安」は、ヒット曲の平均的なスペクトルの傾き（Pestana ら, AES 2013・2017）から作っています。
- 処理前の音が自動で B に入り、試聴音量が「ラウドネス一致」になります。「元の音に戻す」で戻せます。かんたん表示で「もう一度仕上げる」を押すと、元の音からかけ直します（重ねがけしません）。
- マスタリングでミックスの問題は直せません。最後は耳で判断してください。

### リファレンス曲に寄せる

「寄せる先」に、1. の「B で比べる」で入れた曲か、8. に保存した曲を選ぶと、ジャンルの目安の代わりにその曲を目標にします（かんたん表示・10.・アルバム仕上げで共通）。

- **音量**：その曲の統合ラウドネス（−24〜−5 LUFS の範囲）。上限は Spotify の推奨どおり、−14 LUFS より大きければ −2 dBTP。音質優先はそのまま働くので、リファレンスが潰れ気味の曲だと手前で止まります。
- **音色**：その曲の 1/6 オクターブの音色との差を、オート EQ で控えめに補正します。
- **ステレオの広さ**：サイド / ミッドのエネルギー比の差を、サイドの音量で ±3 dB まで合わせます。
- コンプの強さはジャンルの設定を使います。
- 確認：リファレンス（−18.0 LUFS・広さ −11.8 dB）に寄せると、仕上がりは −18.0 LUFS、広さの差 6.3 dB → 2.4 dB、音色の差は低域 2.2 → 1.2 dB・高域 −2.2 → −1.5 dB でした。

LANDR の資料にもあるとおり、権利を持っていない曲をリファレンスとしてアップロードすることには注意が必要です（このツールでは曲は外部に送信されません）。

### 音割れ（クリップ）の修復

波形の頭が平らに切れた所（最大値付近が 2 サンプル以上続く所）を、前後の音から最小二乗 AR 補間（Janssen ほか 1986）で作り直します。本当の値は「クリップの高さ以上・同じ符号」のはずなので、それを満たさないサンプルはクリップの高さに固定して、残りを解き直します。

- 10. の「修復」タブで単独に使えるほか、おまかせ仕上げでは、音割れが見つかった曲だけ自動で最初に修復します（フィルタを通すと平らな頭の形が崩れるため、すべての処理の前）。
- 修復タブで直した場合は、直した波形が元のピークを超えるので、元のピーク以下になるよう全体の音量を下げます。

テスト信号を 3 / 6 dB クリップさせ、元の音との誤差（クリップした所）がどれだけ小さくなったか：

| 素材 | 3 dB クリップ | 6 dB クリップ |
|---|---|---|
| 和音（3 つの正弦波） | 25.6 dB 改善 | 19.5 dB 改善 |
| ベース＋キック＋小さいノイズ | 13.5 dB 改善 | 3.5 dB 改善 |
| ピンクノイズ＋キック | 1.1 dB 改善 | 2.5 dB 改善 |
| 合成ミックス（クリップ部分の主成分がノイズのスネア） | 0.0 dB（変化なし） | 0.0 dB（変化なし） |

ノイズのような音（スネア・シンバルなど）の削れた部分は前後から予測できないので、原理的にほとんど戻せません。低音の山（キック・ベース）はよく戻ります。悪化した例はありませんでした。3 次曲線で山を描く方法も試しましたが、多くの素材で AR 補間より悪かったので採用していません。

### パート別の音量（10. の「パート別の音量（AI）」タブ）

AI（Meta の HTDemucs）で、曲をボーカル・ドラム・ベース・その他の 4 つに分け、それぞれの音量を変えます（例：ボーカルだけ +2 dB）。分けたパートは WAV で書き出せます。

- 仕上がりは「元の音 ＋ Σ（ゲイン − 1）× 各パート」。すべて 0 dB なら元の音とまったく同じで、AI が分けきれなかった成分も失われません。
- 初回だけ、モデル（180,534,758 バイト）を Hugging Face からダウンロードし、SHA-256 で照合してからブラウザ（IndexedDB）に保存します。次回からはダウンロードしません。**音声はどこにも送信しません。** 実行には [ONNX Runtime Web](https://onnxruntime.ai/) 1.20.1 を jsDelivr から読み込みます（この機能を使うときだけ）。
- 推論は Web Worker で行います（画面は固まりません）。WebGPU が使えれば WebGPU、使えなければ WASM（CPU）。44.1 kHz 以外の曲は、このツールの高品質なサンプルレート変換で 44.1 kHz にして分け、元に戻します。
- モデル：[HTDemucs](https://github.com/facebookresearch/demucs)（Meta・MIT）を [demucs-web](https://www.npmjs.com/package/demucs-web)（timcsy・MIT）が ONNX にしたもの。配布元は [ptasior/pizu-audio-models](https://huggingface.co/ptasior/pizu-audio-models)（元のファイルと同じ SHA-256 と明記されたミラー、固定リビジョン `74331d1e`）。STFT と逆 STFT は demucs-web と同じ約束事で、このツールで実装しています。

確認したこと：

- STFT → 逆 STFT：正弦波で 164 dB 一致（区間の中央）。区間の端の誤差は、区間を 25% 重ねてつなぐ重みでほぼ消えます。
- 正解の分かっている合成ミックス（16 秒）を分けた SDR：ドラム 23.7 dB・ベース 20.6 dB・その他（合成の和音）−5.8 dB・ボーカル（合成の母音）1.8 dB。4 パートの合計は元の音と 32.4 dB 一致。Node（onnxruntime-node）とブラウザ（onnxruntime-web・WASM）で同じ値でした。合成の和音や母音は本物の楽器・声とかけ離れているため、低い値は実際の曲での性能を表しません（実際の曲での評価はまだしていません）。
- 速さ：16 秒の音を、ヘッドレスの Chromium（WASM・CPU）で約 55 秒（曲の長さの約 3.5 倍）。WebGPU での速さは、確認できる環境がなく未確認です。
- 中止はすぐ効き（Worker ごと終了）、2 回目以降は保存したモデルを使う（ダウンロード要求 0 件）ことを確認しました。

### 試して見送ったもの：AI 曲の高域のシャリシャリ（shimmer）対策

高域（6〜16 kHz）の成分が時間方向に細かく明滅するのを抑える処理を 2 通り・6 設定試しました。人工の明滅を足した音での改善（きれいな音との距離 4.33 → 3.84〜4.06 dB）と同じくらい、明滅のないきれいな音も変えてしまう（0.70〜1.90 dB）ため、音質を下げるおそれがあると判断して入れていません。

### 上級者向けの調整（くわしい表示の 10. →「上級者向けの調整」）

- **手動 EQ**：バンドごとに種類（ピーク・シェルフ・ハイパス・ローパス）・周波数・Q・ゲインと、かける対象（左右 / ミッド / サイド）を指定できます。「オート EQ の提案を表に入れる」で自動の提案から始めて細かく直せます。設定はブラウザに残ります。周波数特性のカーブを左右・ミッド・サイド別に表示します。
- **リニアフェーズ（ゼロ位相）**：各段を前向きと後ろ向きに通して位相のずれをなくします（書き出し前のオフライン処理なので可能）。打楽器の前に小さなプリリンギングが出ることがあります。
- **コンプの数値指定**：比率・圧縮量（曲の大きい部分での目標ゲインリダクション）・アタック・リリース。
- **リミッターの数値指定**：先読み・保持・リリース（最短〜最長）。
- **処理後のグラフ**：コンプとリミッターが「どこで、どれだけ抑えたか」の時間変化（50 ms ごと）と、処理前・処理後・目安の音色の重ね表示。

### 音質の検証（実測値）

処理の質は、テスト信号で数値を測って確かめています（実際の楽曲での聴感テストはまだ行っていません）。

| 項目 | 結果 |
|---|---|
| リミッター：正弦波を 6 dB 押し込んだときの THD+N | 25 Hz〜1 kHz で −129 dB 以下（改良前は 50 Hz で −36.8 dB） |
| コンプ：強め（4 dB 圧縮）の THD+N | 30〜37 Hz で −70 dB 以下、45〜63 Hz で −82 dB 以下、80 Hz 以上で −97 dB 以下（改良前は 40 Hz で −45 dB） |
| ラウドネスの合わせ込み | 目標との差 0.1 dB 以内（ミックス想定の合成信号、−9 / −14 LUFS） |
| トゥルーピーク | 上限 −1 dBTP を超えない（解析と同じ精密な方法で確認） |
| 低域のモノラル化 | サイドの 60 Hz を −62 dB まで除去、1 kHz のサイドとミッドは変化なし |
| リニアフェーズ EQ（1 kHz・+6 dB） | 中心 +6.000 dB、位相 0.000°（100 Hz〜8 kHz）、インパルス応答の左右差 1.9×10⁻⁹ |
| M/S EQ（サイドに +6 dB） | ミッドだけの音は変化 0（ビット単位で同じ）、サイドだけの音は +6.00 dB |
| 16bit 書き出しのディザ | ディザなしで −104 dB だった量子化歪み（5 次高調波）が雑音に埋もれる。雑音レベル −96.3 dBFS（TPDF の理論値どおり） |

## 配信・納品の条件（3. 公開前チェックの下）

読み込んだファイルのヘッダ（WAV / AIFF / FLAC）から、ビット深度・整数か浮動小数点か・サンプルレートを読み、各社の公開資料の条件と照らします。

| 配信先 | 項目 | 条件（出典） |
|---|---|---|
| Spotify | 音量 | −14 LUFS にそろえて再生（[Loudness normalization](https://support.spotify.com/us/artists/article/loudness-normalization/)） |
| Spotify | トゥルーピーク | −1 dBTP 以下。−14 LUFS より大きいマスターは −2 dBTP 以下（同上） |
| Apple Digital Masters | ビット深度 | 24bit PCM。16bit を 24bit にした水増しは不可（[Apple Video and Audio Asset Guide](https://help.apple.com/itc/videoaudioassetguide/en.lproj/static.html)） |
| Apple Digital Masters | サンプルレート | 44.1 / 48 / 88.2 / 96 / 176.4 / 192 kHz、アップサンプル不可（同上） |
| Apple Digital Masters | トゥルーピーク | −1 dBTP 以下（BS.1770-4）（同上） |
| CD（Red Book） | 形式 | 16bit・44.1 kHz・ステレオ |

- **水増しの検出**：24bit のファイルでも、全サンプルが 16bit の格子に乗っていれば「実際は 16bit の音」と判定します。
- **アップサンプルの検出**：88.2 kHz 以上のファイルで、22 kHz 付近より上が急に空になっていれば「アップサンプルの可能性」と判定します（高域まで音がある本物の 96 kHz では出ないことを確認）。
- 確認：本物の 24bit・16bit の水増し・96 kHz へのアップサンプル・32bit float・16bit の各テストファイルで、期待どおりに判定されました。

## トゥルーピークの測り方

BS.1770 の 4 倍オーバーサンプリングでピークのありそうな位置を探し、その近くを ±128 タップのカイザー窓 sinc で 1/16 サンプル刻み（＋放物線補間）まで細かく補間して求めます。4 倍の格子では高域の強い音で読み落とすためです。

- 以前の版は、候補を 200000 か所で打ち切っていたこと、また強くクリップした広帯域ノイズでは BS.1770 の 4 倍 FIR が想定より低く読むことから、最大 0.47 dB 読み落とすことがありました（合成信号での確認）。
- 今の版は打ち切りをなくし、候補の幅を広げたうえで、まず 1/4 サンプル刻みの 3 点だけを精密に計算し、1/cos(π/8) を掛けても今の最大に届かない位置は細かい計算を省いて速くしています。
- 合成信号 400 通り（ナイキスト付近の正弦波・ホワイトノイズ・クリップしたノイズ・矩形波・インパルス・チャープ、半数はリミッター通過）で、全数計算に対して読み落としがないことを確認しました。
- 速さ（ブラウザ・1 チャンネル）：リミッターで強く潰した 3 分の音で 6.5 秒 → 2.8 秒、60 秒のマスター音源で 0.94 秒 → 0.79 秒。

## 再生機器のシミュレーション（上のバーの「再生機器」）

スマホのスピーカー・ノートPC・安いイヤホン・車のスピーカー・テレビ・モノラルで聴いたときの音を、EQ（とスマホ・モノラルでは左右を混ぜる処理）で大まかに真似て再生します。A / B どちらにもかかります。

- **実機を測ったデータではありません。** 小さいスピーカーは低音が出ない、中高域が目立つ、といった一般的な傾向を、私が設定した EQ で近似したものです（市販の MixChecker などは実機の測定にもとづくとしています）。低音が消えてベースが聞こえなくならないか、ボーカルが埋もれないか、といった大きな問題の確認向けです。
- 確認：オフラインでノイズを通して測ると、設計した特性との差は 200 Hz 以上で 0.1 dB 以内でした。
- 起動時は毎回「そのまま」に戻ります（気づかずに近似の音で判断しないように）。

## 書き出し

WAV 24bit / WAV 16bit（TPDF ディザ・CD 向け）/ WAV 32bit float / FLAC 24bit / FLAC 16bit（ディザ）。FLAC はビット単位で WAV と同じ値になることを確認しています。

サンプルレートは「元のまま / 44.1 / 48 / 88.2 / 96 kHz」から選べます（10. の書き出し）。かんたん表示とアルバム仕上げの「CD 用」は、16bit・44.1 kHz に変換して書き出します。16bit のディザは変換の後にかけます。

### サンプルレート変換

窓付き sinc（カイザー窓・減衰 140 dB）の有理比の多相フィルタです。出力レート / 入力レートを約分した L/M の L 通りの位相の係数を前もって計算するので、位相の近似がありません。通過帯域は 20 kHz まで、阻止帯域は低いほうのナイキスト周波数から。ツール内の変換（AI 分離・コーデック確認・結合）もすべてこれを使います。

| 項目 | ブラウザ標準（Chrome の OfflineAudioContext） | このツール |
|---|---|---|
| 48 → 44.1 kHz の 10 kHz / 20 kHz | −1.26 dB / −5.28 dB | 0.000 dB / 0.000 dB |
| 23 kHz の折り返し（→ 21.1 kHz） | −7.1 dB | −148.6 dB |
| 44.1 → 48 kHz の像（21 kHz → 23.1 kHz） | — | −183.2 dB |
| 理想の正弦波との誤差（1 kHz / 19 kHz） | — | −148.2 / −143.1 dB（float32 の丸めの限界は −153.8 dB） |
| 3 分のステレオ（48 → 44.1 kHz）の変換時間 | — | 約 8 秒（Node・1 スレッド） |

- 実際の曲（48 kHz の MP3）を 44.1 kHz・16bit で書き出すと、統合ラウドネスとトゥルーピークは ffmpeg の測定で元と同じ（−14.8 LUFS・−2.8 dBTP）、40 Hz〜18 kHz の帯域ごとのパワーの差は 0.003 dB 以内でした。
- 以前の版は AI 分離などでブラウザ標準の変換を使っていました。同じ曲の AI 分離で、4 パートの合計と元の音の一致が 25.3 dB → 30.4 dB に上がりました。

## 自動で解析するもの・しないもの

- 読み込むと自動で解析：ラウドネス・ピーク・ダイナミクス（PLR・PSR・DR）・周波数バランス・ステレオ・BPM・キー・構成・公開前チェック・配信コーデックの確認（くわしい表示のときだけ。2. のチェックで切り替え可）
- 9. 音響・振動解析（騒音計・心理音響・次数解析・伝達関数など測定・工業向け）は、最初は隠しています。「9. を表示する」で出せて、どれも「計算」を押したときだけ動きます。

## 編集（10. 編集・書き出し）

- **基本編集**: 切り出し・削除・無音化・無音挿入、フェードイン/アウト、ゲイン、ピーク/ラウドネスのノーマライズ
- **書き出し・結合・分割**: 5. のマッチ EQ や 9. のフィルタを音に反映、WAV/FLAC 書き出し（タグ付き）、複数ファイルの結合、構成区間・マーカー・一定長・無音での分割（ZIP）
- **分離・修復・ピッチ/時間**: 元のツールの機能
- **コード譜・TAB 譜**: コード譜は小節をダブルクリックで書き換え、TAB 譜は「手で編集する」で自由に直して保存

編集した音は「元の音に戻す」で、編集前に戻せます。MP3 への書き出しはできません（WAV / FLAC）。
